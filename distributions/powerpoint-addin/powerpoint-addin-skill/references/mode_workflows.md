# Mode workflows

## Create

Establish the objective, audience, decision/action, source boundary, image
policy, and constraints. Extract a decision-critical register with stable IDs
for objectives, numeric targets, guardrails, decision conditions, constraints,
and required evidence. Build the evidence ledger, governing thought,
answer-first storyline, title strip, and semantic visual plan. Bind every
required register item to a visible slide element. Apply the normal
Title, Confidentiality, Contents, content, Qualification, Backcover sequence
unless the user confirms another. Use only verified native PowerPoint layouts
and objects. Classify every slide and complete both QA passes. Reconcile the
register to the actual deck; planning-only coverage fails.

## Targeted Modify

If scope is unclear, ask once whether only named edits or broader improvements
are authorized. Snapshot order, IDs, layouts, masters, notes, hyperlinks,
relationships, media, embeddings, unsupported objects, and protected shapes.
Mark only actual changes as `modified_in_task: true`. Preserve everything
outside scope and do not normalize the whole deck for a local edit. Put broader
ideas in the report as `Suggested only — not applied to the PPTX`. If an edit
cannot be isolated safely, explain the consequence before broadening scope.

## Review and Improve

Inventory what works before editing. Change sequence, wording, or composition
only when it improves the argument, usability, evidence integrity, or audience
decision. Do not replace facts, blueprints, branding, fixed artwork, or sound
content for stylistic uniformity. Preserve unsupported objects through the
recovery ladder. Run whole-deck communication, evidence, visual,
accessibility, and structural QA. A review-only request remains read-only.
